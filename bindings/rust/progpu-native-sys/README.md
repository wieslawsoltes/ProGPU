# progpu-native-sys

Raw Rust bindings of the ProGPU native C ABI (`progpu_native.h`, ABI version 5) and of the
wgpu-native WebGPU C ABI the engine runs on (`webgpu.h` and `wgpu.h` of wgpu-native
`33133da`, webgpu-headers `aef5e42`), generated by `bindgen` (`regenerate.sh`).

The libraries are loaded at run time (`Runtime::load`). The build script prepares them for the
target, from (in this order):

- `PROGPU_NATIVE_SDK_DIR`, a directory with `include/`, `runtime/` and `sdk/`;
- the ProGPU sources: `PROGPU_SOURCE_DIR`, or the ProGPU checkout the crate is part of (a git
  submodule of ProGPU in an application's repository, for example). The engine
  (`src/ProGPU.Native`) is built with CMake (Ninja when present; Clang, or `clang-cl` on Windows,
  `PROGPU_NATIVE_CXX_COMPILER` to choose another) into `OUT_DIR`, incrementally, against the
  wgpu-native runtime of `Silk.NET.WebGPU.Native.WGPU` 2.23.0 and the pinned `webgpu.h` and
  `wgpu.h`, each verified by its SHA-256. The bindings then run the engine of the sources they
  were built with, including changes to the engine not yet in a package;
- else (the published crate) the pinned NuGet packages of this version (`ProGPU.Backend.Native`,
  `ProGPU.Native.Sdk` and the wgpu-native runtime), downloaded once into a cache
  (`PROGPU_NATIVE_CACHE`, else the user cache directory), verified by their SHA-256 and extracted
  for the target.

Crates that compile C or C++ against the SDK read `DEP_PROGPU_NATIVE_INCLUDE`,
`DEP_PROGPU_NATIVE_SDK` and `DEP_PROGPU_NATIVE_RUNTIME`.

`tests/headless.rs` creates a wgpu-native device, the engine on it, renders a frame of rectangles
and reads it back.
