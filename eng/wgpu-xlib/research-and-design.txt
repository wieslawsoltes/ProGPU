Explicit Xlib EGL dependency investigation — 2026-10-18
Status: reviewed dependency integration in progress; production package and source qualification pending.

Original evidence: identical public preview69 multi-window binary succeeds on
headless X11 (2.642199s) and fails before first presentation on owned GNOME50
Wayland/Xwayland (2.645667s), run39084639920. Software llvmpipe, not GPU hardware.
The original EGL implementation chooses Wayland at instance creation independently
of the Xlib surface supplied later. Do not repair by replacing a live Inner:
its destructor destroys the context and terminates the EGL display.

Design comparison and scope:
Startup: one explicit connection/context per GL instance; no repeated display
probing, context replacement or per-frame connection. No timing improvement claim.
Layout/shaping/fallback fonts/variable fonts/DPI/subpixel/hinting: unchanged.
Display lists, visibility culling, glyph/texture/path cache keys and eviction,
demand uploads, worker preparation and GPU batching/compute: unchanged. Existing
owner-scoped caches retain the same device; no cross-context resource reuse.
Device-loss/atlas generations: existing recovery recreates a complete instance;
no silent reuse of a failed or different display generation is admitted.
Ownership: source connection remains borrowed and must outlive source windows.
Owned native connection, EGL context and display stay together until the last
actual surface/adapter context lease retires. Reject aliasing with the source
and any live explicit backend. Ordinary initialization remains independent.
ABI: add a named versioned optional entry point; keep standard WebGPU descriptors
unchanged. The existing native surface wire supplies screen0, so the first native
entry point must reject other screens rather than claim unsupported transport.
